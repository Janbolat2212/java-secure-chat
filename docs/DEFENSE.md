# Как показать проект за 5–7 минут

1. **До 1 минуты:** задача — показать защищённую передачу сообщений в клиент-серверном Java-чате.
   AES шифрует текст, RSA передаёт AES-ключ. База данных для задания не нужна.
2. **1 минута:** открыть UML и показать ChatClient, ChatServer, ClientSession и CryptoService.
   У каждого клиента собственный AES-ключ. Сервер читает текст и заново шифрует для адресата.
3. **2 минуты:** запустить сервер и два клиента; отправить сообщение с казахскими буквами,
   ответить, затем отправить сообщение несуществующему получателю.
4. **1 минута:** показать проверку fingerprint и объяснить, почему ключ нельзя принимать без проверки.
   Показать в демо отказ при неправильном fingerprint и изменённом сообщении.
5. **1 минута:** запустить JUnit, показать итог и примеры тестов неверного ключа, изменения и повтора пакета.
6. **До 1 минуты:** ограничения — учебный протокол, доверенный сервер, нет сквозного шифрования,
   регистрации и сохранения переписки. Показать README и историю реальных изменений.

Перед защитой нужно уметь объяснить:
- Зачем одновременно RSA и AES? RSA защищает небольшой ключ; AES используется для сообщений.
- Что такое GCM-тег? Значение, позволяющее проверить целостность и подлинность пакета при знании ключа.
- Зачем IV? Он должен быть уникален для каждого шифрования с тем же ключом.
- Что хранится в GitHub? Код и документация; приватные ключи и содержимое переписки не сохраняются.
- Что проверяет JUnit? Автоматически сравнивает ожидаемое поведение с реальным, включая случаи ошибок.
