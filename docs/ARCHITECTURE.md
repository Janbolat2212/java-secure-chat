# Архитектура и соответствие UML

Основой остаются `RESEARCH (3).md` и три исходных изображения UML в корне.
Это дополнение отражает реализованную программу; исходные картинки не заменены.

| Класс | Ответственность |
|---|---|
| ChatServer | Принимает подключения, маршрутизирует сообщения, хранит RSA-пару |
| ChatClient | Проверяет сервер, отправляет и принимает сообщения |
| ClientSession | Состояние одного клиента на сервере |
| CryptoService | JCA: RSA-OAEP, AES-GCM, fingerprint |
| EncryptedMessage | Получатель, номер, IV, шифротекст и тег |
| SecureChannel | Счётчики двух направлений, защита от повтора, чтение/запись конвертов |
| Protocol | Ограниченные по размеру бинарные поля и UTF-8 |
| ChatMessage | Ответ сервера: WELCOME, CHAT или ERROR |
| Main / Demo | Консольный интерфейс и проверяемая демонстрация |

## Последовательность подключения и переписки

```mermaid
sequenceDiagram
    actor A as Клиент Alice
    participant S as Сервер
    actor B as Клиент Bob
    A->>S: TCP-подключение
    S-->>A: Версия протокола и открытый RSA-ключ
    A->>A: Проверить заранее доверенный fingerprint
    A->>A: Создать случайный AES-ключ A
    A->>S: Имя Alice и RSA-OAEP(AES-ключ A)
    S->>S: Расшифровать AES-ключ A
    S-->>A: WELCOME, защищённый AES-GCM(A)
    B->>S: Аналогичный обмен с отдельным AES-ключом B
    A->>S: AES-GCM(A): сообщение для Bob
    S->>S: Проверить номер, адресата и тег; расшифровать
    S->>B: AES-GCM(B): отправитель Alice и текст
    B->>B: Проверить тег и номер; показать сообщение
    alt Изменение или повтор пакета
        S->>S: Отклонить пакет, закрыть соединение отправителя
    else Получатель не подключён
        S-->>A: Зашифрованный ERROR
    end
```

## Формат и границы доверия

Данные передаются через `DataInputStream`/`DataOutputStream`: длина поля (4 байта), затем байты.
Версия/маркер — `SCH1`. Сетевой конверт ограничен 8192 байтами, пользовательский текст — 4096.
Номер сообщения, направление и получатель аутентифицируются через AAD.
IV формируется из 4-байтового префикса направления и 8-байтового номера.
Счётчики начинают отсчёт с нуля; серверный WELCOME тоже занимает номер.
Один AES-ключ используется только в одном подключении. На переполнение счётчика требуется переподключение.

Имя отправителя сервер берёт из своего объекта ClientSession, а не из содержимого сообщения.
Это защищает от подмены отправителя внутри текущего соединения, но **не является проверкой личности**.
Сервер доверенный и имеет доступ к открытому тексту. После отключения сеанс удаляется.
