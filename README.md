# Java Secure Chat

**Тема №15: «Гибридті шифрлаумен қауіпсіз хат алмасу».**
Учебный проект по компьютерной безопасности: два Java-клиента обмениваются
сообщениями через сервер. RSA-OAEP защищает передачу сеансового AES-ключа,
а AES-256-GCM шифрует сообщения и обнаруживает их изменение.

**Состояние: рабочая предварительная версия `0.9.0-SNAPSHOT`, не финальный релиз.**
Интерфейс консольный. SQL, регистрация и хранение истории в проект не входят.

## Быстрый запуск в Windows / VS Code

Требуется **JDK 21**. Отдельно устанавливать Maven не нужно: в проект включён
[официальный Maven Wrapper](https://maven.apache.org/tools/wrapper/).
Первый запуск требует интернета для загрузки Maven и тестовых библиотек.

1. Открыть **папку проекта целиком** в VS Code: File → Open Folder.
2. В терминале этой папки выполнить:

```powershell
.\mvnw.cmd verify
java -jar target/secure-chat.jar demo
```

Либо открыть `run-demo.cmd`: он соберёт проект, запустит тесты и демонстрацию.
В VS Code также есть Terminal → Run Task → **2. Run demo**.
После загрузки Java-проекта можно выбрать **Demo: encrypted chat** в Run and Debug.

Linux/macOS: `./mvnw verify`, затем та же команда `java -jar ... demo`.

## Живой чат: три терминала

Сначала собрать проект командой выше. Во всех терминалах открыть папку проекта.

**Терминал 1 — сервер:**
```powershell
java -jar target/secure-chat.jar server
```
Сервер слушает только `127.0.0.1:5555`. Он создаёт новую RSA-пару в памяти и
записывает **только публичный отпечаток** в `.runtime/server.fingerprint`.

**Терминал 2 — Alice:**
```powershell
java -jar target/secure-chat.jar client Alice
```

**Терминал 3 — Bob:**
```powershell
java -jar target/secure-chat.jar client Bob
```

После подключения обоих клиентов у Alice ввести:
```text
/to Bob Сәлем, Bob!
```
У Bob появится сообщение от Alice. Для ответа:
```text
/to Alice Привет! Сообщение получил.
```
Выход клиента: `/quit`. Остановка сервера: `Ctrl+C`.
После перезапуска сервера заново подключить клиентов: ключи и отпечаток меняются.
Имена состоят из 1–24 латинских букв, цифр, `_` или `-`, чувствительны к регистру.
Сообщение — непустое, до 4096 байт UTF-8. Кириллица, казахские буквы и emoji поддерживаются.
Если старый терминал Windows искажает буквы, перед запуском выполнить `chcp 65001`.

## Подключение с другого компьютера (необязательно)

Сервер: `java -jar target/secure-chat.jar server 5555 0.0.0.0`.
Клиент: `java -jar target/secure-chat.jar client Alice SERVER_IP 5555 TRUSTED_SHA256`.
Заменить `SERVER_IP` и `TRUSTED_SHA256` реальными значениями.
Отпечаток получить лично у оператора сервера или по другому доверенному каналу,
а не из того же непроверенного подключения. Автоматической настройки firewall нет.
Базовая проверенная демонстрация работает на одном компьютере.

## Как устроена защита

1. Клиент сравнивает SHA-256 отпечаток RSA-ключа сервера с заранее доверенным.
2. Создаёт случайный AES-256 ключ и передаёт его через RSA-2048 OAEP
   с SHA-256 и MGF1-SHA-256.
3. Сообщения защищаются `AES/GCM/NoPadding` с тегом 128 бит.
4. Для каждого подключения новый AES-ключ. IV — 12 байт: разные префиксы
   направлений + возрастающий счётчик. IV не повторяется с тем же ключом.
5. Направление, номер и получатель входят в проверяемые дополнительные данные (AAD).
   Повторные, переставленные и изменённые пакеты приводят к закрытию соединения.
6. Сервер проверяет сообщение и заново шифрует его отдельным ключом получателя.

Криптография реализована через стандартную [Java JCA/JCE](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/javax/crypto/Cipher.html).
Собственных шифров и Java-десериализации сетевых объектов нет.

## Проверки

```powershell
.\mvnw.cmd test
```

Используется [JUnit 5](https://docs.junit.org/5.13.4/user-guide/).
Есть криптографические, протокольные и интеграционные тесты с реальными TCP-соединениями.
Результат первой проверки: **44 теста, 0 ошибок, 0 пропусков** (19.11.2026).
Подробности: [TESTING.md](docs/TESTING.md). Полный вывод Maven — в `target/surefire-reports/`.
Сообщения `Connection rejected/closed` в тестах ожидаемы для специально испорченных пакетов.

## Ограничения безопасности

- Это учебный протокол, не прошедший независимый аудит; для реальных секретов не предназначен.
- **Сервер видит открытый текст. Сквозного end-to-end шифрования нет.**
- Имена — псевдонимы текущего подключения, не подтверждённые личности; нет паролей и учётных записей.
- Нет прямой секретности (forward secrecy), сохранения истории, офлайн-доставки или подтверждения прочтения.
- Имена при подключении, адресат в конверте и размеры пакетов не скрыты от наблюдателя.
- Файл локального fingerprint доверен только при доверии к компьютеру и папке проекта.
- Ограничены размер пакетов, число соединений (32) и время обмена ключами (15 секунд).
  Полной защиты от перегрузки и медленного чтения в учебной версии нет.
- Приватный RSA-ключ и AES-ключи не сохраняются в файлы и не выводятся в журнал.
  `.runtime`, `.env` и файлы ключей исключены через `.gitignore`.
